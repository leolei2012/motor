# 工程设计规范

> 本规范约束整个 MC_BASE 仓库（motor_control、bootloader 等各工程）的代码分层与组织方式。
> 具体某个功能的设计细节见 `docs/develope/` 下对应文档。

## 1. 分层架构

工程按职责划分为固定层级，自下而上：

```
┌─────────────────────────────────────────┐
│  app/          应用层（业务编排/主循环体）  │
├─────────────────────────────────────────┤
│  middleware/   中间件（胶水层，双向）       │
├─────────────────────────────────────────┤
│  drivers/      驱动层（设备封装）           │
├─────────────────────────────────────────┤
│  hal/          硬件抽象层（外设实例）       │
├─────────────────────────────────────────┤
│  mcal/         MCAL（厂商 HAL/LL/CMSIS）  │
├─────────────────────────────────────────┤
│  bsp/          板级支持包（入口/时钟/中断） │
└─────────────────────────────────────────┘
   辅助：config/（配置）  utils/（平台无关工具）  third_party/（第三方库）  tests/（测试）
```

## 2. 各层职责

### bsp（板级支持包）
- **入口 main.c**：只做「初始化 + 主循环」，不写业务。
  - 无 RTOS：主循环就是 `while(1)`。
  - 有 RTOS：main 只做初始化，主循环交给 RTOS 线程。
- 时钟树、启动文件、链接脚本、中断向量分发（`bsp_it.c` 只把中断转给对应驱动）。
- 板级初始化编排：`bsp_board_init()` 内部**调用各 hal 的 init**，自己不含实现细节。

### hal（硬件抽象层）
- 外设实例的薄封装（gpio / usart / tim / adc / nvic 等），**不含设备语义**。
- **初始化实现在 hal，由 bsp（或 app）调用**——hal 只负责「怎么配」，上层决定「配成什么样」。
- 例：`hal_gpio` 只提供 `write(port, pin, level)` 这种纯引脚操作，**不认识 LED/电机**。

### drivers（驱动层）
- 具体设备/功能的封装：`drv_usart2`（串口功能）、`drv_output`（开关量输出）、`drv_motor` 等。
- 用 `bsp_config.h` 的引脚宏做「设备 → 物理引脚」映射，持有设备语义与默认状态。

### middleware（中间件 / 胶水层）
- 协议栈、服务组件的装配：modbus + bootloader 适配器 + 串口等。
- **双向调用**：向上可被 app 调，向下可调 drivers / hal / 第三方库。这是中间件区别于其他层的特权。

### app（应用层）
- 业务编排：`app_xxx_init()` + `app_xxx_poll()`。
- 只关心「做什么」，不碰具体引脚/寄存器。

### 辅助层
- **config/**：全局配置（功能开关、频率、版本号、引脚宏）。
- **utils/**：平台无关工具（CRC、滤波器、环形缓冲、PID）。
- **third_party/**：第三方库（bootloader、MB-RTU、uart_control、FlashDB、log 等），不改其内部结构。
- **mcal/**：厂商 SDK（STM32Cube HAL/LL/CMSIS），**不改**，只读引用。
- **tests/**：单元/集成测试。

## 3. 依赖方向（硬规则）

```
app ──> middleware（双向）──> drivers ──> hal ──> mcal
  └────────────────────────────> hal ──> mcal
                                  └──────> bsp（配置/引脚）
```

- 上层可调用下层，下层**不可**反向调用上层。
- **middleware 例外**：它是胶水层，可上下双向调用。
- app / drivers / middleware **不直接碰 mcal**，一律经 hal。
- 换板只改 bsp（+config），hal / drivers / middleware / app 不动。

## 4. 目录结构（bootloader 工程示例）

```
bootloader-v1.0/
├── bsp/          src/{main.c, bsp_board.c, bsp_it.c, system_*.c} + include/ + startup/ + linker/
├── hal/          include/{hal_gpio.h, hal_nvic.h, hal_usart2.h, hal_tim7.h} + src/
├── drivers/      include/{usart2, output}/ + src/{usart2, output}/
├── middleware/   include/boot/ + src/boot/
├── app/          include/boot/ + src/boot/
├── config/       project_config.h、platform.h
├── utils/        check_algorithm 等平台无关工具
├── third_party/  bootloader / MB-RTU / uart_control / FlashDB / log.c
├── mcal/         STM32Cube_FW_G4（厂商 SDK）
└── project/      MDK-ARM 工程文件
```

## 5. 模块命名

| 层 | 前缀 | 示例 |
| --- | --- | --- |
| bsp | `bsp_` | `bsp_board_init` |
| hal | `hal_` + 外设名 | `hal_gpio_write`、`hal_usart2_init`、`hal_nvic_init` |
| drivers | `drv_` + 设备名 | `drv_usart2_send`、`drv_output_set` |
| middleware | `middleware_` + 模块名 | `middleware_boot_poll` |
| app | `app_` + 模块名 | `app_boot_init` |
| 第三方库 | 库自身前缀 | `bl_`、`mb_`、`uart_control_` |

- 目录按「层/模块」两级：`drivers/src/usart2/`、`middleware/src/boot/`。
- 头文件放 `include/`，实现放 `src/`，一个模块一对 `.c/.h`。

## 6. 初始化归属

| 初始化 | 归属 | 谁调用 |
| --- | --- | --- |
| 时钟、GPIO 时钟、NVIC | hal 实现 | bsp（`bsp_board_init`） |
| USART/TIM 外设 | hal 实现 | app（按需，如 `app_boot_init`） |
| uart_control 实例、MB-RTU 从机、bootloader 库 | 各层自己实现 | app 编排 |

- 原则：**hal 提供实现，bsp/app 决定调用时机与参数**，不在 bsp 里写寄存器级实现。

## 7. 移植边界

- **换芯片**：只改 `mcal/`（厂商 SDK）和 `hal/`（外设实例封装）、`bsp/`（启动/时钟/引脚）。drivers/middleware/app 不动。
- **换板（同芯片）**：只改 `bsp/` + `config/`。hal/drivers/middleware/app 不动。
- **换通信协议**：只改 middleware 里的适配器（如 bootloader 库的 `adapter/modbus`），引擎与 drivers 不动。
- **第三方库可复用**：芯片无关逻辑（bootloader 引擎、MB-RTU、uart_control）放 `third_party/`，通过端口/适配器接入，不内嵌芯片细节。

## 8. 关键设计约定（已定稿）

1. 主循环归 main（bsp），无 RTOS 时 `while(1)`；有 RTOS 时交给线程，main 结构不变。
2. NVIC 集中到 `hal_nvic`，统一管理、观察直观。
3. hal_gpio 纯物理（`port + pin`），设备语义归 `drv_output`（持有引脚映射 + 有效电平 + 默认关）。
4. 串口在 hal 叫 `hal_usart2`（外设），在 drivers 叫 `drv_usart2`（功能）。
5. middleware 是胶水层，双向调用。
6. 上电校验、IAP 下载、copy/commit 等 bootloader 业务逻辑全部进 `third_party/bootloader` 库，main/各层只做接线。
